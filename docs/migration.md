# 本地迁移

本次采用“建立统一项目并保留原件”的整理方式，没有移动或删除旧技能、旧工作树、桌面快捷方式、登录态和开机启动项。

| 原有内容 | 整理方式 |
| --- | --- |
| Codex `wechat-ai-reply` 技能主线 | 保留原件；行为约定和核心逻辑由较新的工作树继承 |
| `wechat-ai-console` 工作树 | 保留原件；其后续工作由 desktop-parity 版本覆盖 |
| `wechat-desktop-parity` 工作树 | 以已提交版本及当前未提交修复作为本项目代码来源 |
| `.codex/state/wechat-ai-reply` | 原地保留，不进入 Git；含真实聊天与密钥 |
| 原桌面快捷方式 / HKCU 启动项 | 未改动，仍按原位置运行 |

## 先独立试用

新项目默认 `~/.wechat-ai`，不会直接继承旧版 live 配置。运行 `wechat-ai init` 后，填自己的模型配置，先用控制台或 shadow 模式验证。

## 使用原来的运行目录

只在本人决定切换时操作：

1. 停止旧守护进程和旧控制台，确认旧自动化不再写状态。
2. 在本地备份原运行目录，备份含凭据和聊天，不要上传。
3. 用 `wechat-ai doctor --state-dir "$env:USERPROFILE\.codex\state\wechat-ai-reply"` 检查。
4. 启动控制台时传同一目录。需要启动新守护进程时先确认该目录的 `daemonMode`；旧配置可能是 `live`。
5. 先验证状态、目标聊天与草稿。只有确实决定启用时才运行 live 守护进程。

本项目不会自动执行这次迁移。不要同时运行两个守护进程，也不要在仍有旧实例时修改开机启动。回退时停止新实例，恢复本地备份，再运行旧入口。
